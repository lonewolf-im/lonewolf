# Supported XEPs and RFC profiles

This reference covers receiving client-to-server (C2S) connections and local account/server behavior on one node. Revisions identify reviewed specifications; support is limited to the roles described below. Source and test links provide representative implementation evidence, not certification of every role or recommendation in a specification.

The default host extensions are `roster,offline,disco,ping,vcard,carbons`. Explicit `hosts.<domain>.extensions` lists replace those defaults. See the [configuration reference](../examples/lonewolf.toml) for settings and limits.

[`lonewolf.doap`](../lonewolf.doap) summarizes these tables in the [XEP-0453](https://xmpp.org/extensions/xep-0453.html) format that software directories read. Update both together.

The [v0.2.0 release](https://github.com/lonewolf-im/lonewolf/releases/tag/v0.2.0) first ships the XEP-0030, XEP-0054, XEP-0199, XEP-0280, and XEP-0297 roles described below. The other listed XEP roles first shipped in v0.1.0.

## RFC foundations

RFC numbers identify fixed documents, rather than mutable protocol version labels. The following profiles apply to the implemented C2S, local and partial S2S roles.

| Document and publication date | Implemented profile, updates and limits | Evidence |
| --- | --- | --- |
| [RFC 6120 (2011-03)](https://www.rfc-editor.org/rfc/rfc6120.html) | Receiving XML streams, STARTTLS, SASL/restarts, resource binding, local stanza addressing and errors. Partial S2S binds one domain pair per unidirectional stream with mandatory STARTTLS and SASL EXTERNAL. Inbound streams enforce addressing, namespaces, sequential dispatch, stream limits, idle timeout and certificate expiry. Inbound messages use recipient policy, received archives, local delivery and offline storage; eligible rejections and interim IQ request errors use separate bounded outbound links with domain-based certificate verification, ordered endpoint attempts and failure backoff. The configured default SASL allowlist is `EXTERNAL`, `SCRAM-SHA-256-PLUS`, `SCRAM-SHA-256`, `SCRAM-SHA-1-PLUS`, `SCRAM-SHA-1`. Normally the wire advertises the four SCRAM mechanisms. EXTERNAL appears first only when enabled on the listener and a verified client certificate supplies an eligible `xmppAddr` identity for the selected host; account existence and authorization are checked during authentication. Both channel-binding types are advertised when any PLUS mechanism is enabled, and neither is advertised otherwise.

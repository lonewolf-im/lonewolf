# Supported XEPs and RFC profiles

This reference covers client-to-server (C2S) connections, optional server-to-server (S2S) federation, and local account/server behavior on one node. Revisions identify reviewed specifications; support is limited to the roles described below. Source and test links provide representative implementation evidence, not certification of every role or recommendation in a specification.

The default host extensions are `roster,offline,disco,ping,vcard,carbons`. Explicit `hosts.<domain>.extensions` lists replace those defaults. See the [configuration reference](../examples/lonewolf.toml) for settings and limits.

[`lonewolf.doap`](../lonewolf.doap) summarizes these tables in the [XEP-0453](https://xmpp.org/extensions/xep-0453.html) format that software directories read. Update both together.

The [v0.2.0 release](https://github.com/lonewolf-im/lonewolf/releases/tag/v0.2.0) first shipped the local XEP-0030, XEP-0054, XEP-0199, XEP-0280, and XEP-0297 roles. The other listed XEP roles first shipped in v0.1.0. Federation support described here is not in a release yet.

## Federation profile

Federation is enabled by default for hosts with a configured certificate and a public DNS name. Operators can disable it globally with `s2s.enabled = false` or for one host with `hosts.<domain>.federation = false`. Hosts without a configured certificate, including the default `localhost`, do not federate. No S2S listener opens while federation is inactive. Global disablement also prevents S2S DNS queries and outbound connection attempts. See [certificate-enabled defaults](../crates/lonewolf-core/tests/protocol/s2s/negotiation.rs#L127), [inactive localhost](../crates/lonewolf-core/tests/protocol/s2s/negotiation.rs#L100), [global disablement](../crates/lonewolf-core/tests/protocol/s2s/negotiation.rs#L155), and [per-host opt-out](../crates/lonewolf-core/tests/protocol/s2s/negotiation.rs#L190).

Peers authenticate with PKIX certificates and SASL EXTERNAL over mandatory STARTTLS. Trust uses the bundled public roots, or exactly the PEM bundle configured by `s2s.tls.trust_anchors_path`. The leaf certificate must explicitly contain `id-kp-serverAuth` in both directions; missing EKU and `clientAuth`-only certificates are rejected. The reference identity is the peer's XMPP domain, not an SRV target or IP address. Accepted names are DNS-ID, including a complete left-most-label wildcard, an `_xmpp-server` SRV-ID, or a domain-only `xmppAddr`. Common Name fallback and certificate revocation checking are not supported.

Each stream binds one local and one remote domain and carries stanzas in one direction. Replies use a separate outbound stream. One outbound FIFO link per domain pair has queue limits by stanza count and bytes; inbound streams have a per-pair limit. Negotiation, idle, shutdown and certificate-expiry bounds also apply. Lonewolf does not implement Server Dialback (XEP-0220), bidirectional streams (XEP-0288), Direct TLS (XEP-0368), stream management for S2S, DANE or POSH.

A registered hosted service can federate only while federation is globally enabled and a current certificate from a federating host covers its domain. Selection uses sorted host order and pins the checked certificate generation for each service TLS configuration in both directions. Service SNI must name that service, or be absent. Managed certificates name only their host and cannot cover distinct service domains. Federated roster subscriptions require account contacts with a localpart; inbound domain-only subscription senders are silently ignored by the roster, and outbound subscriptions to domain-only contacts remain unsupported.

Queue admission does not confirm remote delivery. Eligible failures return `resource-constraint` for a full queue, `remote-server-not-found` for disabled federation or resolution failure, and `remote-server-timeout` for connection, TLS or negotiation failure. Asynchronous establishment failures can bounce non-error messages, IQ get/set requests, and subscription presence; other presence and IQ results/errors are dropped. Error stanzas never generate error replies. During failure backoff, eligible new stanzas receive the cached failure without another connection attempt. Stanzas whose write has started are not replayed after connection loss; queued stanzas whose writes have not started can use a new connection. Shutdown drops and counts remaining queued stanzas. See [bounce eligibility](../crates/lonewolf-core/src/s2s/outbound/bounce.rs#L96), [interrupted writes](../crates/lonewolf-core/src/s2s/outbound/link.rs#L529), and [queued shutdown drops](../crates/lonewolf-core/tests/protocol/s2s/lifecycle.rs#L209).

The linked automated scenarios use local Lonewolf instances and scripted peers. They do not establish interoperability with another implementation or live public federation; that verification remains [a separate task](https://github.com/lonewolf-im/lonewolf/issues/567).

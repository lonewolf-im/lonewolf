# XEP-0199 conformance evidence

Lonewolf implements the authenticated, bound C2S server responder and local entity routing described by [XEP-0199 2.0.1](https://xmpp.org/extensions/attic/xep-0199-2.0.1.html), Final, dated 2019-03-26, namespace `urn:xmpp:ping`. The design baseline for [tracker #458](https://github.com/lonewolf-im/lonewolf/issues/458) is commit [`abac35af2b3ebe5d1e54fb8f8af016cadd6ff857`](https://github.com/lonewolf-im/lonewolf/tree/abac35af2b3ebe5d1e54fb8f8af016cadd6ff857). Source links below identify exact test symbols in this checkout.

## Behavior and configuration

**New Ping coverage:** supported server and authorized account GETs return empty IQ results. An omitted destination selects the authenticated account. Full-JID requests go to that exact client; its result or error returns through generic IQ routing even when the Ping extension is disabled.

**Local policy:** another bare account requires recipient-roster `from` or `both` permission. Owner requests need no presence. Authorization precedes payload validation, so hidden and missing accounts have matching errors. A bare pong does not prove a resource is online. Directed presence grants only full-resource visibility.

**Local policy:** server/account payload validation requires empty content, including no whitespace, and permits only payload `xml:lang` metadata, including an empty reset. Namespace declarations are allowed. Other attributes, text and children produce `modify/bad-request`. This profile is informed by the schema, with a language exception; strict attribute and whitespace rejection are not XEP prose requirements. Endpoint-bound content remains the endpoint's responsibility.

**Local configuration policy:** the default extension list is `roster,offline,disco,ping`. Explicit lists replace defaults, and Ping and Disco can be selected independently in either order. There are no Ping option keys. Per-host Ping and discovery handlers independently follow the target host.

**New Ping coverage:** Ping registers feature metadata in both discovery scopes without enabling a discovery handler. With Disco enabled, disco-info exposes that metadata exactly once per scope and provides XEP-0199 §5 discovery. A Ping-only host answers Ping but rejects disco-info and disco-items as unsupported; that explicit configuration does not provide §5 discovery.

**Deferred role:** proactive server pings, heartbeat intervals/timeouts, disconnect-on-timeout, latency metrics, S2S, components, cluster routing, stream-management liveness, and capability-consuming clients are outside this responder. Registered services retain their handlers. Endpoint disappearance during a request does not promise a later reply or exactly-once handling.

## Address and error matrix

For requests without client `from`, `sender` is the authenticated full JID and `target` is the normalized requested address. Existing generic errors may omit `to`; supported handler replies use `sender`. A forged sender never redirects a Ping handler reply.

| Request | Response | `from` | `to` | Payload |
| --- | --- | --- | --- | --- |
| Supported host GET | Empty result | Host domain | Sender | None |
| Supported owner/authorized bare GET | Empty result | Target bare JID | Sender | None |
| Supported omitted-target GET | Empty result | Omitted | Sender | None |
| Supported malformed payload | `modify/bad-request` | Host/bare target, or omitted | Sender | Original Ping |
| Hidden or missing bare account | `cancel/service-unavailable` | Target bare JID | Sender | Original Ping, valid or malformed |
| Unsupported QName, SET, disabled host/account | `cancel/service-unavailable` | Target | Omitted | Original request payload |
| Rejected request envelope | `modify/bad-request` | Supported host target | Sender | Error only; missing ID becomes empty ID |
| Authorized full JID | Client request and peer reply | Authenticated sender/peer full JID | Exact recipient full JID | Endpoint-owned |
| Denied, missing or disconnected full JID | `cancel/service-unavailable` | Exact requested full JID | Sender | Original Ping |
| Host domain/resource | `cancel/service-unavailable` | Exact requested address | Sender | Original Ping |
| Nonlocal domain, bare or full JID | `cancel/remote-server-not-found` | Requested target | Omitted | Original Ping |
| Valid or malformed response with no local recipient | Silent drop | None | None | None |

Policy and admission can reject a request before Ping dispatch. Policy rejection of a response becomes a silent drop. A real full-resource response does not require presence permission and is exempt from recipient admission.

The parser's transport-split, completed-rejection and pending mid-token controls establish completion before dispatch. Ping uses that parser; it does not add a separate partial-stanza parser or a timing-based negative assertion.

[RFC 7622 erratum 4534](https://www.rfc-editor.org/errata/eid4534) is Verified and corrects the domain mapping reference to RFC 5895. [Erratum 4560](https://www.rfc-editor.org/errata/eid4560) is Verified and preserves legal leading resource spaces. [RFC 9844 §3](https://www.rfc-editor.org/rfc/rfc9844.html#section-3) replaces RFC 7622's obsolete zone-ID reference; wire zone-ID rejection remains unchanged. [RFC 6120 erratum 4741](https://www.rfc-editor.org/errata/rfc6120) is Held for Document Update: missing and explicitly empty IDs retain their published distinction. RFC 7590/8553 updates concern inherited TLS/DNS behavior and introduce no Ping responder mechanism.

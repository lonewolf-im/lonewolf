# Lonewolf v0.2.0

Lonewolf v0.2.0 adds discovery, account profiles, and message synchronization
for local XMPP clients. It remains a pre-1.0 server for accounts on the domains
you host. Federation and full XMPP compliance remain on the [roadmap](../ROADMAP.md).

## Client features

- Service Discovery (XEP-0030) answers information and items queries for served
  domains and local accounts, with resource visibility based on authorization.
- vcard-temp (XEP-0054) stores account profiles across restarts. Owners replace
  their profiles; authenticated local users can retrieve them, including when
  the owner is offline. Account deletion also deletes its vCard.
- XMPP Ping (XEP-0199) answers eligible server and account pings. It does not
  send proactive heartbeats.
- Message Carbons (XEP-0280) lets clients enable sent and received message copies
  for each session. Stanza Forwarding (XEP-0297) supplies the copy envelopes.
  Clients must enable Carbons again after reconnecting.

The [standards reference](../STANDARDS.md) records the reviewed revisions,
supported roles, limits, and verification evidence. Stanza Forwarding support
is limited to Carbons copies; this release does not add message archives,
stream resumption, or avatar synchronization.

## Operations and tooling

- The server reports readiness and bound C2S and metrics addresses through
  `NOTIFY_SOCKET` for service managers.
- Accepted C2S connections use `TCP_NODELAY` to send small writes without
  Nagle delays.
- The new [lonewolf-bench tool](../../crates/lonewolf-bench/README.md) measures
  idle connections, message delivery, and connection churn against local or
  remote servers. It records run artifacts and compares compatible runs.
- Stanza errors include explanatory text. A cancelled stanza flush preserves
  the stream-error reply path.
- Dependencies were updated. Tests use explicit synchronization, and nightly
  CI checks for flaky tests.

## Upgrading from v0.1.0

The default host extension list is now
`["roster", "offline", "disco", "ping", "vcard", "carbons"]`.
An explicit `hosts.<domain>.extensions` list replaces the defaults. Existing
configurations that list only `roster` and `offline` keep that selection; add
the new extensions to enable them. Ping, vCards, and Carbons work independently
of Disco, but feature discovery requires Disco.

Stored vCards are public to authenticated local users. The default write limit
is 262,144 serialized UTF-8 XML bytes per profile. Set
`hosts.<domain>.vcard.max_bytes` to a value from 1 to 1,048,576 to change it;
the listener's complete-stanza limit also applies.

The default `limits.c2s.profiles.<name>.max_stanza_bytes` increases from
262,144 to 524,288 bytes. Explicit limits keep their configured values.
The [configuration reference](../../examples/lonewolf.toml) lists all settings.

Existing Redb databases gain a vCard table when opened, without rewriting
account records.
